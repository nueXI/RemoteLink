# RemoteLink — Deployment Guide (Updated)
_Last updated: 2026-06-12_

> **Supersedes:** `deploy-2026-06-11.md`
> **Breaking change:** Backend must now run via **Task Scheduler**, not IIS. See [Why Not IIS](#why-not-iis).

---

## Overview

RemoteLink is a local-network web tool for PC↔phone file transfer, real-time messaging, and screen viewing.

| Layer | Technology |
|---|---|
| Backend | ASP.NET Core 10 + SignalR |
| Frontend | React + TypeScript + Vite |
| Hosting | **Task Scheduler** (user session) |
| Auth | Simple password via `appsettings.json` |

The backend (Kestrel) serves both the API and the React frontend as static files from `wwwroot/`. Everything runs on **one port**.

---

## Why Not IIS

IIS worker processes (`w3wp.exe`) run in **Windows Session 0** — isolated from the interactive desktop. The screen capture feature uses `Graphics.CopyFromScreen` which requires access to the interactive desktop (Session 1). In Session 0 this throws `"The handle is invalid"` regardless of app pool identity.

**Task Scheduler with "Run only when user is logged on"** starts the process in the user's interactive session, giving full desktop access.

> If you don't need screen capture, IIS still works for Files + Chat. See `deploy-2026-06-11.md` for that setup.

## Publishing the Backend

### First deploy (or when process is not running)

```powershell
cd "D:\projects\_PersonalProject\RemoteLink\RemoteLink.Api"
dotnet publish -c Release -o "..\BackendPublish"
```

### Re-deploy while process is running

The `.exe` is locked while running. Kill the process first:

```powershell
# Stop the running backend
Get-Process -Name "RemoteLink.Api" -ErrorAction SilentlyContinue | Stop-Process -Force

# Wait for process to exit
Start-Sleep -Seconds 1

# Publish
cd "D:\projects\_PersonalProject\RemoteLink\RemoteLink.Api"
dotnet publish -c Release -o "..\BackendPublish"
```

Then start the Task Scheduler task manually or re-login.

> **Note:** `dotnet publish` overwrites `appsettings.json` from source. Re-apply your password after each publish if you changed it in `BackendPublish\appsettings.json`.

## Task Scheduler Setup (First Time)

1. Open **Task Scheduler** (`Win + R` → `taskschd.msc`)
2. Click **Create Task** (not Basic Task — you need full options)

### General tab
- Name: `RemoteLink Backend`
- ✅ **Run only when user is logged on**
- ❌ Do NOT check "Run with highest privileges" — elevated processes are still session-restricted for GDI access
- Configure for: Windows 10 or later

### Triggers tab
- **New** → At log on → Specific user → your Windows account

### Actions tab
- **New** → Start a program
  - **Program/script:** `D:\projects\_PersonalProject\RemoteLink\BackendPublish\RemoteLink.Api.exe`
  - **Start in:** `D:\projects\_PersonalProject\RemoteLink\BackendPublish\`
    ← **Required.** Relative paths (`Uploads/`, `ChatLogs/`, `logs/`) resolve from this directory.

### Settings tab
- ✅ Allow task to be run on demand
- If the task is already running: **Do not start a new instance**

### Test
- Right-click the task → **Run** to start it immediately without logging off
- Check Task Manager for `RemoteLink.Api.exe`
- Open `http://localhost:5173` in a browser to verify

## Firewall Rule

Allow the port through Windows Firewall so phones on the LAN can connect.

```powershell
# Triggers UAC prompt (run from a normal terminal)
Start-Process netsh -ArgumentList 'advfirewall firewall add rule name="RemoteLink" dir=in action=allow protocol=TCP localport=5173' -Verb RunAs -Wait
```

Replace `5173` with your configured port if different.

> Verify: `netsh advfirewall firewall show rule name="RemoteLink"`

## Configuration Reference (`appsettings.json`)

```json
{
  "Kestrel": {
    "Endpoints": {
      "Http": { "Url": "http://0.0.0.0:5173" }
    }
  },
  "RemoteLink": {
    "Password": "changeme",       // login password — change before use
    "UploadPath": "Uploads",      // relative to Start In dir, or absolute
    "ChatLogPath": "ChatLogs"     // daily chat log storage
  },
  "FileLogger": {
    "FilePath": "logs",
    "MaxFileSizeBytes": 10485760,
    "MaxFileCount": 10,
    "MinimumLevel": "Information"
  }
}
```

**Port:** Change `Url` to use any free port. Update the firewall rule to match.

## Troubleshooting

### Screen shows "Stream unavailable" or no frames appear
- **Cause A:** Process is running elevated ("Run with highest privileges" ticked in Task Scheduler).
  - **Fix:** Uncheck "Run with highest privileges" — elevated processes cannot access GDI desktop surfaces.
- **Cause B:** Task Scheduler task is not configured to run in user session ("Run only when user is logged on" not set).
  - **Fix:** Recreate the task with "Run only when user is logged on" selected.
- **Cause C:** 4K display at high DPI scaling — partial capture.
  - **Fix:** Already handled in code via `Application.SetHighDpiMode(PerMonitorV2)` in `Program.cs`. Rebuild and redeploy.

### App won't start / port already in use
- Another process is using port 5173.
- **Check:** `netstat -ano | findstr :5173`
- **Fix:** Change `Kestrel.Endpoints.Http.Url` in `appsettings.json` to a different port, and update the firewall rule.

### Files and messages work but phone can't connect
- **Cause:** Firewall rule missing or wrong port.
- **Fix:** Add/recreate the firewall rule for the correct port.

### Chat history not loading
- **Cause:** `ChatLogPath` directory doesn't exist or wrong `Start In` path in Task Scheduler.
- **Fix:** Confirm `Start In` is set to the `BackendPublish\` directory so `ChatLogs/` resolves correctly.

### Published appsettings.json overwrites my password
- **Fix:** After each `dotnet publish`, re-edit `BackendPublish\appsettings.json` and set your password.
- **Better fix:** Use environment variables or a separate `appsettings.Production.json` excluded from source.

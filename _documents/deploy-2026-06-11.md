# RemoteLink — Deployment Guide
_Last updated: 2026-06-11_

---

## Overview

RemoteLink is a local-network web tool for PC↔phone file transfer and real-time messaging.

| Layer | Technology |
|---|---|
| Backend | ASP.NET Core 10 Minimal API + SignalR |
| Frontend | React + TypeScript + Vite |
| Hosting | IIS (Windows) |
| Auth | Simple password via `appsettings.json` |

The backend serves the frontend as static files from its `wwwroot/` folder. Everything runs as a **single IIS site** on a single port.

---

## Prerequisites

### 1. .NET 10 Hosting Bundle
Required for IIS to host ASP.NET Core apps. Even if the .NET 10 SDK is installed, the Hosting Bundle is a separate install.

- Download from: `https://dotnet.microsoft.com/download/dotnet/10.0`
- Under **.NET 10.0**, download **Hosting Bundle** (not Runtime or SDK)
- Run the installer, then restart IIS:
  ```
  iisreset
  ```

### 2. IIS with required features
Make sure these Windows features are enabled:
- Internet Information Services
- World Wide Web Services → Application Development → ASP.NET 4.x (needed even for Core)
- Internet Information Services → Web Management Tools → IIS Management Console

Enable via: **Control Panel → Programs → Turn Windows features on or off**

### 3. Node.js (build machine only)
Required to build the frontend. Not needed on the deployment target if you pre-build. Version used: v23.9.0 / npm 10.9.2

## Building the Frontend

The frontend builds to `RemoteLink.Client/dist/`. After building, the `dist/` contents must be copied to `BackendPublish/wwwroot/`.

```bash
cd RemoteLink\RemoteLink.Client
npm run build
```

Then copy `dist/*` → `BackendPublish\wwwroot\`:

```powershell
# PowerShell — clears wwwroot then copies fresh build
Remove-Item "D:\projects\_PersonalProject\RemoteLink\BackendPublish\wwwroot\*" -Recurse -Force
Copy-Item "D:\projects\_PersonalProject\RemoteLink\RemoteLink.Client\dist\*" `
          "D:\projects\_PersonalProject\RemoteLink\BackendPublish\wwwroot\" -Recurse
```

## Publishing the Backend

### Via Visual Studio
Right-click `RemoteLink.Api` → **Publish** → use the existing `FolderProfile` which targets `BackendPublish/`.

### Via CLI
If IIS is not running the app (first deploy or app is stopped):
```bash
cd RemoteLink\RemoteLink.Api
dotnet publish -c Release -o ..\BackendPublish
```

If the site is **already running in IIS**, the DLL will be locked by `w3wp.exe`. Use the `app_offline.htm` trick to gracefully stop it first:

```powershell
# 1. Take site offline (IIS detects this file and stops the app)
Set-Content "D:\projects\_PersonalProject\RemoteLink\BackendPublish\app_offline.htm" "Deploying..." -Encoding UTF8
Start-Sleep -Seconds 2

# 2. Publish
cd "D:\projects\_PersonalProject\RemoteLink\RemoteLink.Api"
dotnet publish -c Release -o "..\BackendPublish"

# 3. Bring site back online (deleting app_offline.htm restarts the app)
Remove-Item "D:\projects\_PersonalProject\RemoteLink\BackendPublish\app_offline.htm" -Force
```

> **Important:** `dotnet publish` overwrites `appsettings.json` with the source version. If you've changed the password in `BackendPublish\appsettings.json`, re-apply it after publishing.

## IIS Setup (First Time)

### 1. Create Application Pool
- Open IIS Manager (`Win + R` → `inetmgr`)
- **Application Pools** → **Add Application Pool**
  - Name: `RemoteLink`
  - **.NET CLR version: `No Managed Code`** ← critical
  - Managed pipeline mode: `Integrated`
- Right-click the pool → **Advanced Settings**:
  - **Start Mode** → `AlwaysRunning`
  - **Idle Time-out (minutes)** → `0`
  - **Start Automatically** → `True`

### 2. Create Website
- **Sites** → **Add Website**
  - Site name: `RemoteLink`
  - Application pool: `RemoteLink`
  - Physical path: `D:\projects\_PersonalProject\RemoteLink\BackendPublish`
  - Port: _(choose any free port, e.g. 5173, 8080)_
- Click OK

### 3. Authentication Settings
- Click the `RemoteLink` site → double-click **Authentication**
- **Anonymous Authentication** → `Enabled`
- All others (Windows Auth, Basic Auth, etc.) → `Disabled`

> If Anonymous Authentication is disabled, IIS returns 401 for every request before ASP.NET Core even starts.

### 4. Folder Permissions
Grant the app pool identity write access to the publish folder:
- Right-click `BackendPublish` → **Properties** → **Security** → **Edit** → **Add**
- Type `IIS AppPool\RemoteLink` → **Check Names** → OK
- Grant **Modify** permission → OK

### 5. Firewall Rule
Allow the chosen port through Windows Firewall so phones on the LAN can connect.

The command requires elevation. Run **one** of the following:

**Option A — in an elevated terminal directly:**
```powershell
netsh advfirewall firewall add rule name="RemoteLink" dir=in action=allow protocol=TCP localport=5173
```

**Option B — trigger UAC from a normal terminal (will prompt for admin):**
```powershell
Start-Process netsh -ArgumentList 'advfirewall firewall add rule name="RemoteLink" dir=in action=allow protocol=TCP localport=5173' -Verb RunAs -Wait
```

**Option C — via GUI:**
1. Search **Windows Defender Firewall** → **Advanced Settings**
2. **Inbound Rules** → **New Rule**
3. Rule type: **Port** → TCP → specific port `5173`
4. Action: **Allow the connection**
5. Profile: check **Private**
6. Name: `RemoteLink`

Replace `5173` with your actual port in all commands above.

> To verify the rule was created: `netsh advfirewall firewall show rule name="RemoteLink"`

## Configuration Reference (`appsettings.json`)

```json
{
  "RemoteLink": {
    "Password": "changeme",       // login password — change this
    "UploadPath": "Uploads"       // relative to app root, or use absolute path
  },
  "FileLogger": {
    "FilePath": "logs",           // relative to app root, or use absolute path
    "MaxFileSizeBytes": 10485760, // 10 MB per log file
    "MaxFileCount": 10,           // keep last 10 files
    "MinimumLevel": "Information" // Trace/Debug/Information/Warning/Error/Critical
  }
}
```

For production, consider using absolute paths to avoid ambiguity:
```json
"UploadPath": "D:\\projects\\_PersonalProject\\RemoteLink\\BackendPublish\\Uploads",
"FilePath":   "D:\\projects\\_PersonalProject\\RemoteLink\\BackendPublish\\logs"
```

## Accessing the App

1. Find your PC's local IP:
   ```
   ipconfig
   ```
   Look for **IPv4 Address** under your Wi-Fi adapter (e.g. `192.168.x.x`)

2. From any device on the same network, open:
   ```
   http://192.168.x.x:5173
   ```
   _(replace port with whatever you configured in IIS)_

3. Enter the password from `appsettings.json`

## Troubleshooting

### Page shows 401 immediately without loading login screen
- **Cause:** IIS Anonymous Authentication is disabled.
- **Fix:** IIS Manager → site → Authentication → enable Anonymous Authentication.

### Login page never loads, browser shows IIS error page
- **Cause:** ASP.NET Core app is not starting (ANCM failed to start the process).
- **Fix:** Enable stdout logging in `web.config`:
  ```xml
  <aspNetCore ... stdoutLogEnabled="true" stdoutLogFile=".\logs\stdout" ... />
  ```
  Create the `logs/` folder, recycle the app pool, reload the page, then check `logs/stdout_*.log` for the error.
- **Common sub-cause:** .NET 10 Hosting Bundle not installed → install it and run `iisreset`.

### Publish fails with "file is locked by w3wp.exe"
- **Cause:** IIS is running the app in-process and the DLL cannot be replaced while it's loaded.
- **Fix:** Use the `app_offline.htm` trick described in the [Publishing the Backend](#publishing-the-backend) section above.

### Files and messages work on PC browser but not on phone
- **Cause:** Firewall blocking the port, or phone is on a different network segment.
- **Fix:** Add a firewall rule for the port (see step 5 of IIS Setup). Confirm both devices are on the same Wi-Fi network.

### SignalR chat connects but messages don't appear
- **Cause:** Usually a CORS issue during development. In production (same origin) this should not occur.
- **Dev fix:** Ensure `vite.config.ts` proxy target matches the actual backend port.

### App starts but uploaded files are going to the wrong folder
- **Cause:** `UploadPath` is relative and resolves to the IIS working directory, not the app root.
- **Fix:** Set `UploadPath` to an absolute path in `appsettings.json`.

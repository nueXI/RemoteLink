# RemoteLink — Deployment Guide
_Last updated: 2026-06-18_

> **Supersedes:** `deploy-2026-06-12.md`
> **What changed:** Paths now resolve relative to the exe directory via `AppContext.BaseDirectory` — `Start In` in Task Scheduler is no longer required for path resolution.

---

## Overview

RemoteLink is a local-network web tool for PC↔phone file transfer, real-time messaging, and screen viewing.

| Layer | Technology |
|---|---|
| Backend | ASP.NET Core 10 + SignalR (Kestrel) |
| Frontend | React + TypeScript + Vite |
| Hosting | **Windows Task Scheduler** (user session) |
| Auth | Simple password via `appsettings.json` |

The backend serves the API and the React frontend as static files from `wwwroot/`. Everything runs on one port.

---

## Why Task Scheduler (Not IIS)

IIS worker processes (`w3wp.exe`) run in **Session 0** — isolated from the interactive desktop. The screen capture feature (`Graphics.CopyFromScreen`) requires access to Session 1 (the logged-in user's desktop). Running in Session 0 throws `"The handle is invalid"` regardless of app pool identity.

**Task Scheduler with "Run only when user is logged on"** starts the process in the user's interactive session, giving full desktop access.

> For a Files + Chat only deployment (no screen feature), IIS still works. See `deploy-2026-06-11.md`.

## Building the Frontend

Run from the project root (`RemoteLink\`):

```powershell
cd RemoteLink.Client
npm run build
```

Copy the built output into `BackendPublish\wwwroot\`:

```powershell
# Run from project root
Remove-Item ".\BackendPublish\wwwroot\*" -Recurse -Force -ErrorAction SilentlyContinue
Copy-Item ".\RemoteLink.Client\dist\*" ".\BackendPublish\wwwroot\" -Recurse
```

## Publishing the Backend

### First deploy (process not running)

Run from the project root:

```powershell
cd RemoteLink.Api
dotnet publish -c Release -o ..\BackendPublish
```

### Re-deploy while process is running

The `.exe` is locked while running. Stop it first:

```powershell
# Run from project root

# 1. Stop the running backend
Get-Process -Name "RemoteLink.Api" -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep -Seconds 1

# 2. Publish
cd RemoteLink.Api
dotnet publish -c Release -o ..\BackendPublish
```

Then start the Task Scheduler task manually or re-login to trigger it.

> **Note:** `dotnet publish` overwrites `BackendPublish\appsettings.json` from source. Re-apply your password after each publish.

## Task Scheduler Setup (First Time)

Open Task Scheduler: `Win + R` → `taskschd.msc`

Click **Create Task** (not "Create Basic Task" — full options needed).

### General tab
| Setting | Value |
|---|---|
| Name | `RemoteLink Backend` |
| Run only when user is logged on | ✅ checked |
| Run with highest privileges | ❌ unchecked — elevated processes lose GDI desktop access |
| Configure for | Windows 10 or later |

### Triggers tab
- **New** → Begin the task: **At log on** → Specific user → your Windows account

### Actions tab
- **New** → Action: **Start a program**

| Field | Value |
|---|---|
| Program/script | `D:\projects\_PersonalProject\RemoteLink\BackendPublish\RemoteLink.Api.exe` |
| Start in (optional) | `D:\projects\_PersonalProject\RemoteLink\BackendPublish\` |

> **Start in** is optional since paths now resolve relative to the exe directory via `AppContext.BaseDirectory`. Setting it anyway is harmless and useful as a CWD reference.

### Settings tab
- ✅ Allow task to be run on demand
- If the task is already running: **Do not start a new instance**

### Test the task
- Right-click the task → **Run** — starts without logging off
- Check Task Manager for `RemoteLink.Api.exe`
- Open `http://localhost:5120` in a browser to verify

## Firewall Rule

Allow the port through Windows Firewall so devices on the LAN can connect.

```powershell
# Triggers UAC prompt — run from a normal (non-elevated) terminal
Start-Process netsh -ArgumentList 'advfirewall firewall add rule name="RemoteLink" dir=in action=allow protocol=TCP localport=5120' -Verb RunAs -Wait
```

Replace `5120` with your configured port if you changed it.

Verify: `netsh advfirewall firewall show rule name="RemoteLink"`

## Configuration Reference (`appsettings.json`)

```json
{
  "Kestrel": {
    "Endpoints": {
      "Http": { "Url": "http://0.0.0.0:5120" }
    }
  },
  "RemoteLink": {
    "Password": "changeme",       // login password — change before use
    "UploadPath": "Uploads",      // relative to exe directory, or absolute
    "ChatLogPath": "ChatLogs"     // relative to exe directory, or absolute
  },
  "FileLogger": {
    "FilePath": "logs",           // relative to working directory (set Start In to exe dir)
    "MaxFileSizeBytes": 10485760, // 10 MB per log file
    "MaxFileCount": 10,
    "MinimumLevel": "Information" // Trace/Debug/Information/Warning/Error/Critical
  }
}
```

**Notes:**
- `RemoteLink.UploadPath` and `ChatLogPath`: relative paths resolve from the **exe directory** (`AppContext.BaseDirectory`). Absolute paths are also accepted.
- `FileLogger.FilePath`: resolved by RunamiLogger, which uses `Directory.GetCurrentDirectory()`. Set `Start in` in Task Scheduler to the exe directory to ensure this also resolves correctly.
- **Port:** Change `Kestrel.Endpoints.Http.Url` to any free port. Update the firewall rule to match.

## Accessing the App

Find your PC's local IPv4 address:
```powershell
ipconfig
```
Look under **Wi-Fi adapter** for `IPv4 Address` (e.g. `192.168.x.x`).

From any device on the same network:
```
http://192.168.x.x:5120
```
Enter the password from `appsettings.json`.

## Troubleshooting

### Screen shows "Stream unavailable" or no frames
- **Cause A:** "Run with highest privileges" is checked in Task Scheduler.
  - **Fix:** Uncheck it — elevated processes cannot access GDI desktop surfaces.
- **Cause B:** Task is not set to "Run only when user is logged on".
  - **Fix:** Recreate the task with that option selected.
- **Cause C:** 4K display at high DPI — already handled via `Application.SetHighDpiMode(PerMonitorV2)` in `Program.cs`.

### App won't start / port already in use
```powershell
netstat -ano | findstr :5120
```
Change `Kestrel.Endpoints.Http.Url` to a different port and update the firewall rule.

### Phone can't connect but PC browser works
- Firewall rule missing or using wrong port.
- **Fix:** Add/recreate the firewall rule for the correct port. Confirm both devices are on the same Wi-Fi network.

### Chat history not loading
- `ChatLogPath` can't be written to.
- **Fix:** Confirm `BackendPublish\ChatLogs\` exists and has write permission for the logged-on user.

### Logs missing or going to wrong folder
- RunamiLogger resolves `FileLogger.FilePath` from `Directory.GetCurrentDirectory()`.
- **Fix:** Ensure `Start in` in Task Scheduler is set to the `BackendPublish\` directory.

### `dotnet publish` overwrites my password
- Re-apply password in `BackendPublish\appsettings.json` after each publish.
- Alternatively: create `BackendPublish\appsettings.Production.json` (excluded from source) and set password there — it will override `appsettings.json` in Production environment.
